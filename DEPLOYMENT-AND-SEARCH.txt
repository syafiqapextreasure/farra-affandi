FARRA AFFANDI — DEPLOYMENT & SEARCH SETUP
Updated: 26 October 2026

This repository contains the complete bilingual website. Bahasa Melayu is the default; English is under /en/.

CLOUDFLARE WORKERS — CONNECT GITHUB
1. In Cloudflare Workers & Pages, create/import a Worker from the GitHub repository syafiqapextreasure/farra-affandi.
2. Select production branch main. Root directory: repository root (leave blank or use /).
3. Worker name: farra-affandi (must match wrangler.jsonc).
4. Build command: npm run build && npm run check
5. Deploy command: npm run deploy
6. Dependency install: npm ci. Use Node 22 or newer.
7. After deploying, add farraaffandi.com as a Custom Domain in the Worker settings. Add www.farraaffandi.com too if you want its redirect; both hostnames must route to this Worker.
8. Confirm HTTPS works, / and /en/ load, /sitemap.xml returns XML and an unknown URL returns HTTP 404.

The repo includes wrangler.jsonc, worker.mjs, package-lock.json and all website images. No API keys, database or environment secrets are required. Do not use SPA fallback: this is a multi-page site with a real 404.
The production canonical host is https://farraaffandi.com. Workers.dev and other preview hostnames receive X-Robots-Tag: noindex, follow. This is intentional; the site becomes indexable on the exact production domain.
The Worker preserves .html routes, redirects /index.html to / and /en/index.html to /en/, and redirects www to the canonical domain. Existing local-file previews still work.

GOOGLE SEARCH CONSOLE — AFTER THE DOMAIN IS LIVE
1. Add a Domain property named farraaffandi.com (no https:// or path).
2. Copy the exact DNS TXT record Google provides and add it in your domain's DNS settings (Cloudflare if it manages your DNS). No verification token has been invented or inserted into the site.
3. Click Verify in Search Console after the DNS record is visible. Retain the TXT record.
4. Submit https://farraaffandi.com/sitemap.xml in Sitemaps.
5. Inspect https://farraaffandi.com/ and https://farraaffandi.com/en/ with URL Inspection; use the live test, then request indexing.
6. Monitor indexing, search queries, mobile performance and Core Web Vitals. Add a real verified business address/service area only when confirmed; archived event locations are not office branches.
Do not submit the workers.dev preview as the production site. Registration, ownership verification, indexing and ranking have not been completed by this code change.

SEO & ANSWER DISCOVERY
- Unique BM/English titles and descriptions, absolute canonicals, reciprocal ms-MY/en/x-default alternate links.
- XML sitemap with 30 canonical pages and language alternatives. 404 pages excluded and marked noindex.
- Person, WebSite, WebPage, ProfilePage, ContactPage, BreadcrumbList and appropriate Service JSON-LD.
- FAQPage JSON-LD mirrors the visible FAQ text. This is semantic markup, not a promise of Google FAQ rich results; Google no longer displays that feature according to its June 2026 documentation update.
- Visible concise answers on the home, hydrogen-session, spa-coaching and events pages.
- Open Graph/Twitter sharing metadata. No keyword stuffing, invented reviews, fabricated credentials, unconfirmed locations or medical outcome promises.
- Google says no special AEO schema or llms.txt is needed. These foundations improve eligibility and clarity, not guaranteed search/AI placement.
- Search intent research and page mapping: KEYWORD-RESEARCH.csv and SEO-RESEARCH.txt. No paid keyword-volume data was available.
